## Rollout, rollback and mixed-worker matrix

| State | Required behavior / allowed recovery | Unsafe shortcut |
| --- | --- | --- |
| Compatible source deployed; schema 001 and routing disabled | Legacy behavior remains authoritative. Deploying compatible source alone does not apply schema 002, install Apps or migrate guides. | Enabling typed routing before the protected schema/tuple exists. |
| Schema 002 installed; explicit typed legacy routing enabled; no handoff | Preserve the historical tuple and verify all old/new workers still route legacy work correctly. Drain pre-router leases before proceeding. | Inferring original destinations from the organization configuration or treating a new registry default as historical evidence. |
| Shadow pin owner-merged; no new authority | Validate exact fetched bytes and failure paths while legacy output remains unchanged. Recover by fixing access/pin validation without adopting shadow content. | Calling a successful shadow build cutover approval. |
| First guide handoff completed; first active pin pending | Keep live reader available, fence publication, retain both bindings and process one genuine new reviewed change through both merges. Expect temporary refusal of unrelated old-pin app builds. | Running pre-router workers, rolling code back to pre-router base, disabling routing, fabricating a bootstrap review or clearing authority/controller state. |
| Content PR created or merged; app review unmerged | Retry the same deterministic content/app intent under fenced leases; keep canonical editing state unchanged for the new route until verified owner app merge. Reviewer Check/admin Run can advance eligible work. | Marking published at content merge, using a different repo because a PR number matches, or abandoning the stored target/receipt identity. |
| App pin merged; deployment pending or failed | Preserve the exact pin and private receipts; canonical editing state may have advanced once. Keep status pending until the exact live A/C proof matches. Retry the build/provider check against the same approved source. | Treating READY/merge as live, rebuilding an older pin after a newer durable intent, or rolling back canonical revisions. |
| Schema-2 release verified live | Rebuild compatible earlier app code with current approved pin and full validation. Content reversions are new reviewed revisions. Keep target credentials as long as historical verification and pending work need them. | Restoring old configuration or an artifact that cannot honor current routing/proof semantics. |
| Explicit Instant Rollback exception | Freeze advancement, inspect the restored A/C and runtime generation, reconcile with the unchanged DB, then verify reader/runtime and normal deployment assignment before resuming. This requires separate operator/user approval. | Assuming an old ready artifact passed today's gate, or assuming new pushes will automatically resume normal domain assignment after rollback. |

Pre-router workers are not made safe merely by the presence of new JSON columns. New workers validate frozen targets; old code does not acquire that check retroactively. The exact-host ingress guard limits ordinary requests to the configured origin, but it does not replace draining in-flight work or planning for the old deployment's cron/configuration during an operator rollback.
